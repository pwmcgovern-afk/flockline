# Sighting pages

Each real finding links to `/sightings/{eBird checklist ID}/{species code}`. The same address works from Insights, the weekly drawer, archived issues, newsletter previews, and future emails. `/api/sighting` and the server-rendered page use the same loader. The loader confirms that the species appears on the checklist before returning a page. If the birder logged a subspecies group or form, the checklist entry is found through eBird's taxonomy `reportAs` mapping, and photo lookups accept that taxon code too.

Source facts and observer notes come from the authenticated eBird checklist API. Notes are excerpts, capped at 25 words in total per checklist and credited to the observer. Missing effort stays missing instead of becoming a zero. Dates remain in the observation's local time.

The detail page describes one species on one checklist. Its only bird count comes from that checklist's observation, shown once near the top. A separate reporting section shows report groups, with the region, requested date window, and every counted checklist linked. Checklists with the same location and start time count as one report group; the checklist total and every link remain visible, with matching entries marked "Same place and start time". The feed does not confirm a shared outing or the same birds. Checklists without a start time are never grouped. Report groups are not independent sightings or distinct birds. A count printed beside a place belongs to that checklist, never the regional maximum. Findings are selected by recency and geographic variety, without `surge` scores, rarity ranking, or movement inference. Titles and descriptions use factual templates; saved regional prose is not rendered on an individual sighting page. Outing metadata is available in the collapsed Checklist details section, with explicit person/species units and missing effort omitted.

## Saved context

The rolling notable feed cannot reconstruct old stories. `saveSightingFindings` saves the headline, regional summary, location and illustration reference to public Blob at `sightings/{subId}/{speciesCode}.json` when Insights or a roundup is built or archived. The write is bounded and best effort: a storage outage must not stop the existing map or weekly send. Readers can still load the source checklist if saved story context is unavailable. Saved-context reads have caller-side deadlines: four seconds for Blob listing and five seconds for content fetching plus JSON parsing. They use AbortError cancellation to avoid SDK TimeoutError retries, and observe late failures without holding up the caller. The sighting loader rebuilds displayed copy from checklist facts under `source-facts-v1`, leaving the original saved observations intact. Ask remains a separate generative feature.

New findings save a structured reporting snapshot with source checklist IDs, dates, locations and per-checklist counts. Counts are derived from these records, never generated prose. Duplicate species/checklist rows from the notable API count once. The feed requests up to 10,000 rows per upstream region; partial coverage is labeled when a request fails or reaches that limit. Nationwide reads start with one country request; if it reaches the limit, every state is re-read separately (three at a time, then refused states are retried twice after short pauses, because eBird refuses fast bursts on one key) and the country rows are kept only for states whose own request failed, which stay labeled partial. The UI always explains that the notable feed may omit other reports.

Older stories without evidence use a separately labeled current seven-day snapshot for the saved region, or the featured state’s Census region, falling back to National if neither is known. This read is cached for 15 minutes and never overwrites historical story text or claims to recover its old totals. A feed failure leaves the featured checklist usable with an unavailable notice.

The September 21, 2026 editions and the September 26 Northeast insights were backfilled at launch.

## Photos

Photos use Macaulay Library's official iframe embed. The file remains hosted by Cornell and includes the contributor, checklist and source links. One frame is loaded at a time; the selector switches between up to six photographs.

The normal eBird API returns photo counts, not asset IDs. `sightingMedia.js` first uses verified references or saved media metadata, then attempts to read the public checklist's photo metadata. It rejects challenge/login pages and never solves challenges or forwards login cookies. Successful discoveries are saved in `sighting-media/{subId}/{speciesCode}.json` through bounded background work, without holding the page response open for a write. Unavailable lookups are retried after a short cache period.

`shared/verifiedSightingPhotos.json` contains references checked against public eBird checklists or the species-filtered Media gallery on September 26, 2026. Each record includes the asset ID, species and credit. A checklist ID is included only when the relationship was verified. Records without one are reference images, never evidence of the particular sighting. This initial set covers all 30 findings in the five September 21 editions and the current four Northeast insights.

Exact-checklist photos always take priority. If none is available, `relatedSightingMedia.js` looks for the same species at the exact eBird location ID, on the featured observation's calendar date or the preceding seven calendar days. It never matches names or coordinates or uses a later date. Verified references are available immediately. Otherwise, it checks at most three distinct candidate IDs already present in the reporting snapshot, confirms their species, location, date and positive photo count through the checklist API, and attempts the existing media lookup. It makes no new regional feed requests. A shared 2.5-second deadline cancels checklist, taxonomy and media work; a failure preserves the page and does not establish that photographs are absent. Related lookup results have a separate cache capped at 200 entries, with 15-minute successes and one-minute misses.

These photographs say "Photographed at this location · Another checklist" and give the photo's own date, photographer and checklist link. The caption explicitly says the same individual is not confirmed. On October 14, 2026, Helen Wang's October 12 Bryant Park Sora checklist `S401810869`, location `L683555`, was verified in Cornell's checklist and species-filtered Media gallery. Its photo assets are `666749436`, `666749437`, `666749438` and `666749439`; `666749440` is video and is excluded. The October 14 featured checklist `S402323216` has no attached photos. The new references preserve that distinction.

If no exact or recent same-location photo is available, a verified image of that species appears with an explicit "different report" caption. If neither is available, the existing species illustration is used when available. A failed media lookup is distinct from a checklist with no attached photographs. Cornell may display its own brief browser check while an embed opens; Flockline does not bypass it.

To add a verified reference, inspect the actual checklist or species-filtered Media results, record its asset ID and photographer, and include `subId` only for an exact checklist match. Verify the resulting page in a real browser. Cornell's embedding guidance is for noncommercial use; revisit permissions before enabling sponsorship or other revenue: https://support.ebird.org/en/support/solutions/articles/48001064570.

## Verification

Run `npm run check`, `npm run test:ui` and `npm run test:ui:webkit`. The fixture suite covers title links, Learn more, direct reload, photo switching, retries and phone overflow. It blocks external requests, so also visually verify at least one real Cornell embed on the deployed page.
